# 产研翻译小助手

面向团队使用的飞书电子表格翻译机器人。用户通过交互卡片提交表格链接和任务参数，机器人读取简体中文、自动识别语言列，调用兼容 OpenAI 接口的模型生成译文，并回填到原表格。

当前提供两种翻译模式：

- **翻译新增内容**：表格新增了一行或多行中文后，补齐这些内容对应的现有语种。
- **新增语种翻译**：在表格末尾新增一个语言列，并翻译整张表中所有有效的简体中文。

机器人只处理独立的飞书电子表格，也支持指向电子表格的 Wiki 链接；不处理普通飞书文档中的表格。

## 用户使用方式

用户进入机器人单聊，或发送任意普通消息，都会收到“使用说明 + 翻译模式入口”卡片。也可以发送“帮助”“使用说明”“说明书”“怎么用”等指令重新打开该卡片。

### 开始前请确认

1. 表格中存在简体中文列，且待处理行的简体中文不为空。
2. 表头中存在可识别的简体中文列和目标语言列。
3. 已将“产研翻译小助手”添加为该表格的文档应用。
4. 机器人拥有表格 **编辑权限**。

### 模式一：翻译新增内容

适合表格新增了一行或多行内容，需要把 **新增内容翻译成已有语种**。

1. 点击“翻译新增内容”。
2. 粘贴 `/sheets/` 或指向电子表格的 `/wiki/` 链接。
3. 起始行只填写数字。
4. 结束行留空时只处理起始行；填写结束行时批量处理行号区间。
5. 单次最多处理 100 行。
6. 如果目标单元格已有译文，机器人会先让用户选择“仅填空白”“覆盖全部”或“取消”。确认 10 分钟后失效。

翻译时，机器人会：

- 自动扫描前 20 行，定位真正的语言表头。
- 自动识别本表已有的目标语言，不需要在代码中预先配置目标语种数量。
- 读取同一行的 `功能版块`、`功能模块`、`说明`、`备注`、`key` 等非语言字段作为语义上下文。
- 参考上一行对应语种的译文，尽量沿用既有术语、固定句式和表达风格。
- 写回前再次检查简体中文是否变化；发生变化的行不会被错误写回。
- 跳过简体中文为空的行，并在结果中说明。

### 模式二：新增语种翻译

适合在现有表格末尾追加一种新语言，并翻译整张表。

1. 点击“新增语种翻译”。
2. 粘贴表格链接。
3. 填写新语言的表头名称，例如“泰语”或 `Thai`。
4. 填写 BCP 47 语言标签，例如 `th`、`fr-CA`、`zh-Hant`。
5. 机器人先展示工作表、表头位置、新增列位置和待翻译行数；用户确认后才调用模型并写入表格。

机器人会参考当前表格的表头风格命名新列：

- 如果现有语言列采用 `Arabic(语言标签ar)`，新列沿用“名称 + 语言标签”格式。
- 如果现有语言列采用 `简体中文`、`意大利语` 等纯名称，新列只使用用户填写的名称。

该模式不会修改现有语言列，只会新增一个语言列并填充简体中文不为空的行。完成卡片会显示成功、失败和因源内容变化而跳过的数量，并提供当前表格链接。

## 支持的表头

机器人扫描前 20 行寻找同时包含简体中文和至少一个目标语言的表头。

支持两类格式：

- 带标签格式：`简体中文(语言标签zh-Hans)`、`English(语言标签en)`。
- 纯名称格式：`简体中文`、`English`、`French`、`意大利语` 等。

带标签格式按照 BCP 47 标签识别；纯名称格式按照完整语言名称或已登记的别名识别。成功新增一种语言后，机器人会把该语言名称和标签记录在 `data/languages.json`，供后续识别同类纯名称表头使用。这是内部能力，不向用户提供独立的“添加语言配置”功能。

## 权限与失败处理

机器人会区分以下情况：

- **无法访问表格**：机器人不能读取目标电子表格或 Wiki 节点。卡片明确提示“机器人无法访问该表格”。
- **没有编辑权限**：机器人能够读取，但写入被拒绝。卡片明确提示“机器人没有编辑权限”。
- **网络暂时不稳定**：连接飞书或模型服务时发生可重试的网络错误，机器人会自动重试，仍失败时提示用户稍后重新发起。

遇到权限问题，请联系表格所有者或管理员：

1. 打开目标表格的权限设置。
2. 添加“产研翻译小助手”为文档应用。
3. 授予机器人可编辑权限。
4. 返回权限提示卡片，点击重新检查或继续翻译。

机器人不能绕过飞书安全机制自行申请或提升权限。

错误卡片中的恢复按钮会尽量回填用户刚才填写的链接、行号或语言信息。最近一次表单内容及待确认任务目前保存在进程内存中，因此服务重启后未完成的任务状态和 10 分钟确认状态不会保留，用户需要重新提交。

## 飞书开放平台配置

### 应用权限

至少开通：

- 读取用户发给机器人的单聊消息。
- 以机器人身份发送消息。
- 查看、评论、编辑和管理电子表格。

具体权限名称以飞书开放平台当前页面为准。修改权限、事件或菜单后，需要创建并发布新的应用版本。

### 事件与回调

选择“使用长连接接收事件/回调”，并订阅：

- 接收消息：`im.message.receive_v1`
- 用户进入机器人单聊：`im.chat.access_event.bot_p2p_chat_entered_v1`
- 机器人自定义菜单：`application.bot.menu_v6`

卡片按钮还需要启用“卡片回传交互”，并同样使用长连接接收回调。

### 机器人自定义菜单

配置推送事件菜单项：

- `翻译新增内容`：`translate_existing`
- `新增语种翻译`：`translate_new_locale`
- `使用说明`：`translation_help`

飞书自定义菜单的实际展示位置受客户端版本和终端能力影响；聊天卡片中的模式按钮是所有用户的主要入口。

## 本地启动

要求 Node.js 20 或更高版本。

```bash
npm install
cp .env.example .env
```

在 `.env` 中填写：

```text
FEISHU_APP_ID=飞书应用 App ID
FEISHU_APP_SECRET=飞书应用 App Secret
AI_API_KEY=模型服务 API Key
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=模型名称
```

`AI_BASE_URL`、`AI_MODEL` 和 `AI_API_KEY` 可替换为其他兼容 OpenAI Chat Completions 接口的模型服务配置。

检查并启动：

```bash
npm run check
npm start
```

终端出现 `ws client ready` 后，再在飞书中测试消息和卡片按钮。

## 兼容的文字命令

卡片是推荐入口，同时保留以下文字命令：

```text
翻译 <飞书电子表格链接> 第15行
翻译 <飞书电子表格链接> 第15-30行
```

普通用户无需记忆该格式。

## 部署注意事项

### 同一个飞书应用只运行一个服务实例

不要同时在本机、Railway 或其他服务器运行使用同一组 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET` 的多个长连接进程。多个实例可能争抢同一事件，造成：

- 新旧卡片随机出现。
- 同一条消息被不同版本处理。
- 按钮点击没有进入预期版本。
- 调试日志与用户实际看到的回复不一致。

从本地切换到云端前先停止本地进程；恢复本地调试前先暂停云端服务。如果无法找到旧部署，可在飞书开放平台重置 App Secret，并只把新 Secret 配置到当前唯一实例。

### 持久化与多实例边界

- `data/languages.json` 当前写入本地文件系统。部署到临时文件系统时，重启或重新部署可能丢失自定义语言别名；生产环境应挂载持久卷或改用数据库。
- 表单恢复、欢迎卡片冷却和待确认任务当前保存在内存中，不支持多实例共享，也不会跨重启保留。
- 当前版本适合单实例部署。若以后需要水平扩容，应把事件去重、表单状态、确认任务和语言注册表迁移到 Redis 或数据库。

## 安全边界

- 不要提交或分享 `.env` 文件。
- 不要在聊天、日志或截图中暴露 App Secret、模型 API Key 或访问令牌。
- 机器人不会修改简体中文列和其他业务字段。
- 新增语种模式不会改写现有语言列。
- 发生网络中断或模型失败时，不应把未完成的翻译标记为成功。
